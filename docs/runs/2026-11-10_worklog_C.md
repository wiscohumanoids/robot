## J2: G1 tracking on LAFAN1
- Data: Unitree's G1-retargeted LAFAN1 CSVs. The official HF repo `unitreerobotics/LAFAN1_Retargeting_Dataset` returns 404;
  used the mirror `Luca-liang/LAFAN1_Retargeting_Dataset` (the fallback `fetch_lafan1.sh` already names). 40 G1 clips available
  (dance1-2, fallAndGetUp1-3, fight1, fightAndSports1, jumps1, run1-2, sprint1, walk1-4, several subjects each).
- Clips chosen: `dance1_subject2` (131 s; the classic BeyondMimic demo clip), `jumps1_subject1` (244 s),
  `fallAndGetUp1_subject1` (168 s). Same files on Mac (`training/tracking/data/lafan1/g1/`, not synced) and VM
  (`~/hsim_data/lafan1/g1/`), sha256 identical.
- Issue: `hf download --include a b c` only fetched 2 of 3 files; downloading by exact filename works.
- `training/tracking/motion_to_npz.py`: mjlab's csv_to_npz always writes /tmp/motion.npz and uploads to W&B. This reuses
  mjlab's MotionLoader and logs the same fields, but writes a chosen path, no W&B, and takes `--robot g1|wisco`.
- `training/tracking/train_g1_tracking.sh <clip>`: converts on first use (GPU), trains `Mjlab-Tracking-Flat-Unitree-G1`
  from the local npz, TensorBoard logging (no W&B), NUM_ENVS 4096, ITERS 15000, save every 250 (mjlab G1 default is 500).
- **One policy per clip = 3 GPU jobs for J2** (J2a dance, J2b jumps, J2c fallAndGetUp).

## VM GPU check (tmux hsim-C-check, 256 envs, 2 iterations each; outputs ~/hsim_runs/_checks/C/)
- Motion npz made on the VM GPU: `~/hsim_data/motions/g1/{dance1_subject2,jumps1_subject1,fallAndGetUp1_subject1}.npz`
  (6574 / 12222 / 8410 frames at 50 Hz), `~/hsim_data/motions/wisco/dance1_subject2.npz` (6574 frames).
- Issue 1: launchers not executable (files written without +x) -> "Permission denied". Fixed with chmod +x.
- Issue 2 (**affects every cuDNN user on this VM**): `CUDNN_STATUS_SUBLIBRARY_LOADING_FAILED` in tracking's conv1d. The
  DLAMI sets LD_LIBRARY_PATH to the system CUDA 13.2 libs, so torch 2.15+cu132 loads a mismatched cuDNN sublibrary.
  With LD_LIBRARY_PATH unset, cuDNN works (tested conv1d both ways). Launchers now `unset LD_LIBRARY_PATH`.
  Velocity jobs are unaffected (MLPs use cuBLAS, not cuDNN); perception / GR00T envs will likely hit it.
- After fixes: G1 and Wisco tracking each ran 2 PPO iterations on GPU (1.2-2.2 s/iteration at 256 envs), ONNX exported.
