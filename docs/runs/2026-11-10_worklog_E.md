## Decisions (and why)
| Decision | Why (numbers from the bench) |
|---|---|
| Ensemble Grounding DINO base + tiny, box threshold 0.30 | Base alone found the fridge in 2/13 views, tiny 8/13 but low precision; ensemble: fridge 8-10/13, sink 16-17/18, precision 0.41-0.45 |
| Prompt chunks of 12 names, max 4 chunks per forward | Long prompts hurt; batching all chunks used 20 GB (over the 15 GB test budget) |
| Lean default vocabulary (12 names) + environment labels + planner targets | Every extra name adds latency and false labels |
| No separate single-name "priority" pass (server `--priority-mode none`) | Solo pass: 13 correct vs 230 phantom detections (hallucinates the asked-for object anywhere); contrastive pass suppressed the target too. Planner targets just go first in the prompt list: small-object recall 0.45 vs 0.20 when not asked for |
| Cross-label suppression (IoU > 0.8 keeps the higher score) | Same door called "cabinet" and "drawer" |
| 3D: nearest depth cluster + MAD band + 2-98 % box, completion for compact objects | Masks leak onto walls behind objects; camera sees only the front surface. Small-object 3D error: median 1.3-1.9 cm, p90 4-6 cm |
| Client sends JPEG + half-res 16-bit PNG depth via stdlib urllib | ROS container has cv2 but no requests/PIL; keeps the tunnel payload small |
| Client subclasses the stub | Fallback to today's exact behaviour if the server is unreachable; automatic switch back via /health |
| LD_LIBRARY_PATH unset for the server | VM default puts CUDA 13.2 libs first; torch then loads the system cuDNN 9.23 instead of its own 9.19 (worked here, broke another env) |

## Precision study (coordinator task, 2026-11-10 afternoon)
Same 36 frames (kitchens l1/l4/l9, re-rendered pixel-identically with a per-pixel object map), same prompts
(lean vocabulary + kitchen labels), measured through the server end to end unless marked offline.

### 1. Scoring audit: what the "false positives" really were
The box-overlap scorer (0.41) counted a detection as wrong unless its box overlapped a ground-truth box of the exact
same label. A mask-based audit (`bench/audit.py`: what does each detection's mask actually sit on?) with crops of
every category showed:
- **Scoring artifacts (75 detections, 15 % of all):** RoboCasa near-synonyms (37: "drawer" on a RoboCasa "cabinet"
  front, "bottle" on the juice bottle), masks over a group of same-kind objects (32: one "drawer" mask over a stack of
  drawer fronts, each its own RoboCasa object), correct detections of objects below the 150-pixel ground-truth cutoff (6).
- **Not artifacts:** RoboCasa "accessory" objects are knife blocks, paper-towel holders and utensil crocks; calling
  them cup/plate/bottle is wrong (the first audit draft treated them as unlabeled, which was too generous).
- **Real errors (255):** forced labels (dishwasher -> "fridge", drip tray -> "plate", utensil crock -> "cup", cabinets
  -> "window", toaster oven -> "oven"), counter-on-floor, and 30 duplicates (base + tiny find the same object).

Scorer v2 (all rules in the docstring of `bench/audit.py`): exact, exact_small, synonym (groups: cabinet/drawer/shelf,
stove/stovetop/range hood/oven, toaster oven/microwave, bottle/juice/bottled drink), group (>= 50 % of the mask on
objects with the label or a synonym), part (cabinet/drawer/shelf on a RoboCasa cabinet carcass) count as correct;
duplicates, wrong (incl. accessories), background count as errors. Strict precision (exact only) is always reported.
Honest baseline: **0.497** (strict 0.349), not 0.41 and not the 0.525 of the first, too generous draft.

### 4. Multi-view confirmation (ROS side, world_model)
- `confirm_views` (default 1 = unchanged stub behaviour; autonomy.launch sets 2 for `perception:=server`).
- A sighting is a new view only if the camera moved >= 0.1 m or turned >= 5 deg since the track's last view (and
  >= 0.3 s later), or after 2 s of persistence from one spot: consecutive frames from one viewpoint repeat the same
  mistakes, so time alone is not a view. Tentative tracks are not published (planner never sees them), get their
  id only when committed, and expire after 15 s unseen. `/world/summary` objects gain `views`; the summary gains `tentative`.
- ROS smoke test (throwaway container): the mug is committed after 2 views, a one-frame phantom plate never reaches
  `/world/summary` and its tentative track expires, plus the earlier checks (request, placement, fallback): PASS.
- Memory simulation on the benchmark (`bench/memory_sim.py`): confirm 1 / 2 / 3 views -> memory precision 0.74 / 0.87
  / 0.85, recall 0.65 / 0.53 / 0.46 (the benchmark's views are far apart; on the robot each object is seen in many frames).
