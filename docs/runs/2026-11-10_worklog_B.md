## v2 recipe as implemented
1. Actions: 15 = `.*_hip_{pitch,roll,yaw}`, `.*_knee`, `.*_ankle_{pitch,roll}`, `waist_{yaw,roll,pitch}` (G1 action scales kept). Observations: all 29 joints (actor obs 85 = 9 + 29 + 29 + 15 + 3).
2. Arms: event term `random_arm_targets` (mode "step"): new goal every U(1,3) s; 30 % default pose, else uniform in [default - 0.6(default-lo), default + 0.6(hi-default)] (soft limits); smoothstep move over U(0.3,1.5) s; its `reset()` writes the default pose right after mjlab clears joint targets on episode reset.
3. Payload: `dr.body_mass` add U(0,1) kg to `left/right_wrist_yaw_link` (point mass; mjlab warns inertia unchanged - fine for a payload).
4. Tracking std 0.25 (lin) / 0.35 (ang).
5. `TurnInPlaceVelocityCommandCfg`: 20 % of resamples pure yaw, |yaw| U(0.3,1.5), not heading/standing/world/forward envs; ang range +-1.5 in every curriculum stage. Measured 21.1 % pure-yaw.
6. Delay: all G1 actuators `delay_max_lag=2` (0-10 ms), lag resampled every 50 physics steps (0.25 s, slowly varying latency).
7. Push x/y +-0.8 m/s.
8. `dr.joint_armature` x0.9-1.1 and `dr.pd_gains` kp/kd x0.9-1.1 at startup; no mass DR.
Also: pose reward and joint-limit penalty restricted to the 15 policy joints (the arms are not the policy's to fix).

## J1b fix (coordinator request): performance-gated curriculum
Why: J1 learned to stand still (velocity error ~0.6 m/s, ~150-step episodes for 700 iterations): tight tracking std
from iteration 0 made partial progress worthless, and every disturbance was at full strength from the start.
- `mdp.difficulty_curriculum` (curriculum term "difficulty", runs on episode resets). Window of 512 finished episodes:
  up 0.1 if mean length > 0.8 x max AND linear-tracking reward per second > 0.5 x its weight; down 0.1 if mean length
  < 0.4 x max. Starts at L = 0.
  - L scales: arm random-target range 0 -> 0.6 of soft range; hand payload max 0 -> 1.0 kg (payload is now a "reset"
    event, `dr.body_mass` add, relative to the default mass so it never accumulates); push 0.5 -> 0.8 m/s.
  - L2 rises only once L == 1: tracking std 0.5 -> 0.25 (lin), 0.707 -> 0.35 (ang). Going down lowers L2 first.
  - Logged: Curriculum/difficulty/{level, level2, arm_range_frac, payload_max_kg, push_mps, std_lin, std_ang,
    mean_len_frac, lin_track_frac}. `set_levels(L, L2)` forces levels (tests / resume).
- Play cfg: no curriculum (arms default, no payload); `eval_commands.py --arms random` sets the 0.6 range explicitly.
- Unchanged: 15 actions, turn-in-place 20 %, delay, kp/kd/armature DR, no mass DR.
Tests: Mac CPU: parameters at L=0 / forced L=0.5 / L=1,L2=1 / back to 0 all correct; synthetic windows: 12 good ->
L 1.0, L2 0.2; good length + poor tracking -> no change; 3 bad -> L2 0, L 0.9; hand mass varies per env at L=1;
3 PPO iterations log Curriculum/difficulty/* every iteration and save checkpoint + ONNX. VM GPU (1024 envs): no NaN;
gate stepped L2 down on short zero-action episodes as designed.

## J1c fix (coordinator, after J1b): arm-aware collisions, safe arm targets, stricter gate, resume
Why: J1b's curriculum hit L = 1 in ~100 iterations, then reward collapsed (28.7 -> 0.6), mostly self_collisions
(-0.70) from scripted arms hitting the body; turning never learned (track_angular ~0.04).
- (a) Self-collision penalty: the G1's whole-body `self_collision` sensor is replaced by three sensors pairing leg links
  with `torso_link` (body), the right-leg subtree (left legs as primaries), and `pelvis` (body); reward
  `mdp.body_self_collision_cost` ORs them per substep (same scale as mjlab's). Test: arms pushed into torso/legs -> 0;
  legs crossed -> 4 (all substeps). VM GPU, L = 1, moving arms, zero action: penalty 0.0/step.
- (b) Arm targets: `arm_ranges.G1_ARM_OFFSETS` (left arm, right mirrored), offsets from default: shoulder pitch -0.9..+0.1
  (forward raise), shoulder roll 0..+0.6 (outward only), shoulder yaw +-0.3, elbow 0..+0.8 (bend only), wrist roll +-0.6,
  pitch/yaw +-0.5; scaled by L (0 -> 1), clamped to soft limits. Contact sweep (`hsim_tasks/tools/arm_contact_sweep.py`,
  3000 sampled poses, legs at default): arm touches body 45.9 % (old 60 %-of-soft-range) -> 1.4 % (new); arm-arm 5.2 % -> 0 %.
- (c) Gate: +0.05 only if episode length > 0.8 max AND linear tracking > 50 % AND angular tracking > 40 % of weights AND
  >= 50 iterations (x 24 env steps) since the last raise; same for L2; lowering unchanged (-0.05 on < 0.4 max).
  New log key Curriculum/difficulty/ang_track_frac. Test: ang 30 % -> hold; all good -> 0.05; immediately again -> hold
  (dwell); +50 iterations -> 0.10; short episodes -> 0.05.
- (d) Resume: `scripts/train_g1_velocity_v2_resume.sh --from <model_N.pt> --log-root <new root>` copies the checkpoint to
  `<root>/g1_velocity_v2/resume_<src run>/` and runs with --agent.resume True --agent.load-run/-checkpoint; the new run is
  written alongside. Curriculum restarts at L = 0. Tested on CPU: loads, trains iterations 2 -> 3, writes model_3.
- Scripts set MUJOCO_GL=egl only on Linux (EGL fails on macOS); empty extra-arg arrays are safe on old bash.

## J1d fix (coordinator): angular-momentum penalty without the scripted arms; start level for resumes
Why: on Wisco, as the level rose, Episode_Reward/angular_momentum went -0.02 -> -1.10: mjlab's `root_angmom` is whole-body
subtree angular momentum, dominated by the scripted arms + payload. Same class of bug as the self-collision one.
- `mdp.bodies_angular_momentum` / `policy_bodies_angular_momentum_penalty`: |L|^2 of the policy-controlled bodies (pelvis,
  12 leg links, waist_yaw_link, waist_roll_link, torso_link) about their combined COM, world frame, current masses:
  L = sum m_i (p_i - c) x (v_i - v_c) + R_i diag(I_i) R_i^T w_i. Weight kept -0.02. Logs Metrics/policy_angular_momentum_mean.
  Correctness: over all bodies it equals mjlab's root_angmom sensor (mean relative error 8e-7, J1c policy).
- Numbers (CPU, J1c model_950 driving, 32 envs, 200 steps):
  | case | whole-body |L|^2 (old) | policy-bodies |L|^2 (new) |
  |---|---|---|
  | walking, L = 0 | 1.353 (cost -0.027/s) | 0.908 (-0.018/s) |
  | walking, L = 1 | 2.711 (-0.054/s) | 1.733 (-0.035/s) |
  | standing (zero command), L = 0 | 0.093 | 0.056 |
  | standing, L = 1 (arms moving + payload) | 0.584 | 0.361 |
  | arms still, hips + waist at 3 rad/s | - | 20.5 |
  The new term still rises with L (the arms shake the torso/pelvis, which the waist/legs can resist) but stays ~0.62x of old.
- `G1_START_LEVEL` env var (default 0; > 1 sets L = 1, L2 = value - 1) -> curriculum param `start_level`. Checked: 0.1 ->
  arm frac 0.10, payload <= 0.1 kg, push 0.53 m/s.
- Curriculum `apply()` now skips event terms that are absent (play/eval configs without pushes).
- CPU resume from J1c model_950 (CUDA checkpoint mapped to a CPU copy for the Mac only): loads, trains 950 -> 951.
  VM GPU (1024 envs, start level 0.1): no NaN.
